# Synthetic data — Paytm Hisaab (PLAN.md §6)

> This file is the schema reference. For how the data was generated, what it means for the build,
> evaluation targets and caveats, read [../DATA.md](../DATA.md).

Generated by `python -m synth.generate` (Python standard library only, fixed seeds, so it is
fully reproducible). Every person, VPA, business and case reference is fictional. Law-enforcement
and notice references carry a `SYN` prefix.

## Layout

```
data/
  reference/hsn_catalog.json     public reference: item -> HSN -> exempt? (+ basis)
  <split>/                       demo | dev | eval | sweep
    visible/                     the ONLY thing agents and skills may read
      transactions.csv           every credit (CR) and debit (DR)
      pos_bill_lines.csv         item lines for POS-billed sales
      merchants.json             merchant profile (incl. linked own accounts)
      merchant_events.json       inputs that arrive: tax notices, freezes, CMP-08 returns
    hidden/                      generator truth: scorer and demo script only
      ground_truth.csv           per credit: true label, reason, exempt/taxable split, cues
      relationships.csv          duplicate_of, refund_of, vendor_refund_for, reversal_of, funds_for, repeat_of
      merchant_truth.json        totals by label, aggregate turnover, crossing date, family, own accounts
      fraud_chains.json          victim -> mule -> mule -> merchant
      demo_scenario.json         (demo only) the four beats, with txn refs and expected answers
```

**Rule:** agent and skill code never opens `hidden/`. That separation is what makes the accuracy number real.

## Splits

| split | merchants | window | use it for |
|---|---|---|---|
| demo  | 1: Sahana Stores, Jayanagar (~13.3k credits) | FY 2025-26 | the four demo beats |
| dev   | 7 archetypes, mixed difficulty (~107k credits) | FY 2025-26 | tune prompts / rules freely |

| sweep | family_kirana at d = 0, 0.25, 0.5, 0.75, 1 (~36k) | Oct 2025 – Mar 2026 | accuracy-vs-difficulty curve |

The dev/eval archetypes are: `veg_vendor` (exclusively exempt), `mixed_kirana`, `family_kirana` ×2
(shared personal/business account), `mobile_accessories` (all taxable, fast growth), `darshini`
(services, ₹20L threshold) and `composition_kirana` (registered, with under-declared CMP-08 quarters).
Each of dev and eval contains one fraud chain and one tax notice. Scoring all ~107k credits with an
LLM is unnecessary: `synth.score` scores whatever subset you predict.

| txn_id | `DM…` / `DV…` / `EV…` / `SW…`, chronological |

## Labels

There are seven true labels. `unclassified` is an output the agent may give, never a truth. Where
PLAN's tags overlap, the generator uses these rules:

- **taxable_supply / exempt_supply.** The label follows the majority of basket value; the exact
  split is in `exempt_value` / `taxable_value`. Exempt vs taxable can only be identified per credit
  when there is a POS bill. For QR-only sales at a mixed shop, estimate the split in aggregate
  (from the POS-bill mix or the merchant's attestation). The scorer reports these two cases
  separately.
- **personal_transfer.** From household family: spouse, sibling, parent, in-law.
- **inter_account.** From an account in the merchant's own name, whether or not it is linked in
  the profile. At d ≥ 0.5 the second own account is *not* linked.
- **non_business.** Loan disbursal, chit-fund payout, festival gifts from friends or extended
  family (amounts like ₹1,001), a hand loan repaid, a rent deposit returned, an insurance claim.
- **refund_reversal.** A supplier sending money back (short supply, crate return), or a failed
  payout reversed.
- **duplicate.** The refunded one of two identical payments, or the later one if neither was
  refunded. Its twin stays a sale. Hard negatives exist: genuine repeat purchases of the same
  amount a few minutes apart (`repeat_of`).
- **Fraud-linked credit.** This is a genuine sale. Provenance and fraud linkage are independent;
  see `fraud_chain_id`.

## Difficulty knob (d = 0 → 1, per merchant)

d controls how often the visible cues appear:

- round amounts
- off-hours timing
- P2P channel vs QR
- surname match (names get abbreviated as d rises)
- UPI notes
- whether the second own account is linked
- the gap between duplicate payments (2 min → 30 min)
- whether the duplicate was refunded at all (95% → 60%)
- whether the refund hit the "wrong" twin

The `cues` column in ground_truth.csv lists the cues each credit actually carries, for error
analysis.

## Threshold truth

**Aggregate turnover = taxable + exempt supplies** (CGST Act s.2(6)). It excludes personal,
inter-account, non-business, duplicates and refunds. The threshold is ₹40L for goods and ₹20L for
services. An exclusively-exempt supplier (`veg_vendor`) need not register even above ₹40L (s.23).
`merchant_truth.json` has `threshold_crossing_date` and `registration_required`.

## Demo world: Sahana Stores (`MID_DEMO_SAHANA`, owner Sahana Gowda, Kannada)

**Beat 1 — attestation.** On Tue 10 Mar 2026 the agent asks about three credits from 8–9 Mar:

- ₹15,000 at 23:04 on Sunday from her own SBI savings VPA → `inter_account`
- ₹7,500 at 13:20 on Monday from spouse Manjunath Gowda via QR → `personal_transfer`
- ₹4,850 at 16:40 on Monday from Raghu Shetty, a bulk buyer seen twice before → a sale (`exempt_supply`)

No other non-sale credits fall on those two days.

**Beat 2 — threshold.** Aggregate turnover crosses ₹40L on **14 Mar 2026**. To demo the
projection, replay with data up to 31 Jan 2026.

**Beat 3 — tax notice.** The notice dated 20 Aug 2026 claims **₹60.98L**. The true breakdown:

| label | amount |
|---|---|
| exempt | ₹32.14L |
| taxable | ₹10.75L |
| own-account | ₹7.36L |
| personal | ₹5.73L |
| loan / chit / gifts | ₹4.26L |
| refunds | ₹0.47L |
| duplicates | ₹0.27L |

Aggregate turnover is ₹42.9L, so she **did** need to register. The pack disputes the ₹61L figure
and says so honestly.

**Beat 4 — freeze.** The account is frozen at 09:30 on Tue 24 Mar 2026 on a Telangana NCRP
complaint:

- disputed credit: ₹4,200 at 19:47 on 21 Mar, POS-billed, UTR given in the freeze event
- decoy: ₹4,200 on 18 Mar from a regular customer
- credits in the 7 days before the freeze: 339

PLAN §11's beat-3 figures (₹41L exempt + ₹13L taxable = ₹54L) would put her far over ₹40L. Use
the numbers above instead.

## Commands

```
python -m synth.generate [--only demo|dev|eval|sweep]
python -m synth.baseline data/eval                      # rule baseline, visible/ only
python -m synth.score data/eval data/eval/predictions_baseline.csv
```

A predictions file needs just `txn_id,label`. Point `synth.score` at your agent's output the same way.
