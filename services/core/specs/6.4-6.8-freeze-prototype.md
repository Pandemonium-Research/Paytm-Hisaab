## Real isolation: 6.4

Expose `isolate(connection, body: IsolateRequest) -> IsolateResponse` in
`app/skills/isolate.py`, wired to the existing evidence-role POST endpoint.

- Validate that the case belongs to the merchant and has opened by the effective cutoff.
  Restrict every rail/evidence lookup to that merchant and cutoff.
- Find the submitted UTR independently of amount/date. Separately find credits of the exact
  disputed amount whose IST date is within the inclusive disputed_date +/- date_window_days.
  `found_by` describes only matches to the selected transaction, ordered utr then amount_date.
- A unique UTR selects its credit. With no unique UTR match, a single amount/date candidate
  may select a credit. An ambiguous set must not arbitrarily select a decoy. A UTR match
  with a contradictory amount/date may be returned with `found_by: [utr]`, visibly showing
  the inconsistency. Never award an amount_date badge just because some other credit matches.
- `same_amount_candidates` includes every other visible credit of that amount in the trailing
  seven-day evidence window [as_of - 7 days, as_of], including the demo's 18 March decoy;
  exclude the selected transaction. Sort by timestamp/txn_id. Do not widen the date-match
  window merely to discover the decoy.
- Attach only a bill whose rails.bills and linked ledger evidence name the matched credit,
  merchant and bill, with sim_at <= cutoff. Lines are ordered by line_no; total must match
  both the payment and the line sum. No unseen/mismatched bill evidence.
- Attach its actual merchant-owned terminal/device/geo only when installed_at <= cutoff
  and required metadata exists. Otherwise device is null.
- `seven_day_credit_count` counts this merchant's visible credits in that same seven-day
  window, including the selected transaction when it falls within it.
- Return validated frozen IsolateResponse, including null/empty results without invented data.

## Real freeze pack build: 6.8 prototype scope

POST /packs remains evidence-only with frozen BuildPackRequest/Response. Validate a visible
merchant-owned freeze case, matching pack_type, sim_at >= opened_at and <= sim_now. WF20 sends
sim_at == opened_at, which is valid. Read the disputed UTR/amount/date from the persisted lien
and call the isolation helper at that cutoff. Never rely on an unbuilt skill's HTTP fixture.

Persist a structured JSON packet and valid PDF with the same real facts:

- Opaque pack ID, case/merchant/business identity, case/build business timestamps in IST,
  original lien/authority/reference facts and explicit SYNTHETIC / SIMULATED / PROTOTYPE stamps.
- Matched credit and its actual UTR, amount/date, independent found_by checks, other same-amount
  candidates explicitly not chosen, bill lines/total, installed device/geo and seven-day count.
- Recorded ledger reference seqs and hashes for evidence used. No invented citations, verdict,
  clearance, bank release or success promise. It is a factual evidence packet for officer review.
- Tier totals describe the **selected disputed payment's evidence**, not an invented fully
  classified year. Include this scope explicitly in JSON and PDF. Tier 1 if an actual bill
  linked before case opening supports the credit without a contradictory visible claim;
  otherwise tier 4 for a relevant later annotation/answer/proposal, tier 3 for a pre-case answer
  to a real system question, tier 2 for a recorded pre-case proposal with no answer. Strictly
  before opened_at counts as pre-case. If no qualifying evidence exists, all four totals are
  zero and the packet says ungraded; never promote a bare credit to rule-backed. Populate all
  four amount/count buckets and use exactly those in pack.built. Full period grading (6.1)
  remains deferred; do not claim it is implemented.
- PDF must wrap long references/names/bill descriptions and paginate without clipping. A
  plain English export is sufficient for this prototype; Kannada PDF shaping/Indic fonts
  and WeasyPrint remain deferred. ReportLab documentation:
  https://docs.reportlab.com/reportlab/userguide/ch2_graphics/ and
  https://docs.reportlab.com/reportlab/userguide/ch5_platypus/ . Escape external text in Paragraphs.

Default artifact root: existing persistent `/runtime/packs` in the container; configurable
via `HISAAB_PACK_DIR` (for tests/local runs). Do not write into the repo, source tree or git.
Name artifacts using the generated opaque pack ID, never client-supplied paths. Write temp
files and atomically replace complete artifacts; do not publish partial files as success.

Use record_pack to persist the ops pack/approval and append pack.built in the same transaction.
Its pdf_sha256 is SHA256 of actual PDF bytes. Metadata must retain JSON/PDF artifact locations,
the payload/facts needed on retries and the same-origin pdf_url used by 6.11 officer detail.
Builds are idempotent for the identical (merchant, case, pack_type, sim_at) request: serialize
with the merchant chain lock and return the original packet/entry/artifacts on retries, with
no duplicate build or approval. A distinct later timestamp can create a newer packet. Hold
the same chain lock before reading evidence so each packet is a consistent build snapshot.
Do not add a resume_url request field; WF20 currently polls and the contracts stay frozen.
